# AI 评审规则（服务器当前口径）

评审服务使用 `deepseek-v4-flash`，对评分达到候选线、未删除且未过期的公告进行两阶段处理。规则版本为 `2026.08.31-governance-v7`，Harness 版本为 `two-stage-v6-fact-object-decision`。

DeepSeek 只负责抽取带逐字摘录的 `source_objects`、`participation`、`business_scope`、`project_stage`、`exclusions`、`risks`；程序负责最终裁决。公告全文只用于校验摘录真假，不直接参与分类。硬排除只读取公告标题和明确采购对象，核心产品只读取 `source_objects`，业务范围只读取 `business_scope`，参与入口只读取 `participation`。单独出现 AIS、VDES、合同、验收、LED 或“智慧航道”等词均不能独立决定通过或排除。

1. DeepSeek 仅抽取可逐字验证的公告事实：采购对象、参与窗口、业务范围、项目阶段、排除事实和待核实事项；
2. 程序再依据已验证事实、时效和硬规则裁决业务桶。模型不能直接决定“通过/排除”。

## 能力范围

- AIS/VDES 岸基站、船载终端、核心网、卫星载荷、船岸/船船通信和远程运维。
- ECDIS、INS、船舶导航集成、智能船舶/无人船艇导航信息系统。
- AIS/VDES 数据、船舶态势、电子围栏、轨迹回放、海上通信导航信息化、渔船/渔港监管、海洋牧场/海上风电/油气平台通航安全平台。
- 方案设计、设备部署、调试、运维、软件升级和数据服务；具体资质、业绩、保密与联合体条件必须逐项人工核验。

## 三类输出

- `direct_opportunity`：公告原文同时证明仍有采购/供货/分包/合作入口，并证明采购对象与上述能力直接匹配。
- `market_intelligence`：业务相关但没有可证实的当前参与入口，例如中标、成交、候选人结果、关闭项目或市场线索。
- `exclude`：明确无关或命中强制排除。

## 强制排除

- 招聘、招录、录用、废标、流标、终止、暂停、作废、合同、验收、环评公示。
- 电力语境中的 AIS（空气绝缘开关设备、变电、电网、开关柜）。
- 普通照明、LED 灯器、普通电子元件、保险、培训、会议、劳务。
- 没有海事通信、导航、船舶信息、通航安全或港航监管实质关联的采购。

单独出现“海事、船舶、AIS、卫星、海洋、港口、智慧港口”等词不构成匹配。施工、疏浚、设计、监理、航标维护，以及仅采购雷达/CCTV/北斗/VHF 单品的项目均须严格按公告原文处理，不能臆测为遨海可直接参与项目。

采购单位属于海事、港航或交通系统，或网页导航中出现“海事监管”等栏目词，也不构成采购范围。公务车、打印机等一般采购对象不得仅因采购方身份进入市场情报。

## 证据与降级

- 每个结论必须保存公告原文短引文；引文不在原文中会被程序丢弃。
- 事实抽取对每类事实和引文长度设上限，避免模型输出被截断；非完整 JSON 会自动重试一次，仍失败保持为 `failed`，不会继续沿用旧结论。
- 普通照明或 LED 灯器命中公告标题/正文时，服务端会直接生成原文依据并裁决为 `exclude`；DeepSeek 的抽取遗漏或错误分类不能覆盖该确定性边界。
- 直接商机若缺少采购入口或能力匹配证据，会自动降为 `market_intelligence`。
- 资格、授权、业绩、联合体、保密等不确定因素只作为风险提示，不能凭空认定可参与。
- 人工结论优先；AI 排除记录在清理前可逐条复核并改为通过。
- 模型返回缺字段、非 JSON、证据无效或接口异常时，系统自动重试一次；仍失败则标为 `failed`，不进入实时或历史商机列表，并保留错误和审计事件供后续重试。
- 旧版未带规则/Harness 版本的结论只在“已保存排除理由明确否定能力范围”的高确定性情形下自动修复；修复前结论会存入审计快照，人工决定和原始商机不自动改写。
