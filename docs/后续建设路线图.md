# 遨海商机雷达｜后续建设路线图（冻结版）

本路线图不替代当前线上功能；每个里程碑均须先完成影响预览、回归测试、备份和人工确认后发布。里程碑 1–5 的基础能力已进入代码：其中 AI 双跑默认仅回放历史已验证证据；只有显式以 CLI `--live` 执行才会调用 DeepSeek，且两者都不会改写历史结论。

## 里程碑 1：生产级代码重构

将抓取、规则、数据库、AI、HTTP API 和前端从大文件拆分为独立模块；不改变已确认的业务规则和用户功能。

已落地：抓取准入策略、来源解析、治理契约、变更影响识别分别为独立模块；保留既有 HTTP 路由与数据库结构。剩余大文件拆分采用小步替换，必须通过同一回归门禁。

## 里程碑 2：AI 双跑评测

选择固定样本，让旧 AI 口径与新 Harness 并行运行；输出逐条差异、证据完整率和人工确认结果。未确认前不批量改历史结论。

已落地：`review_evaluations` 独立账本与 `--dual-run`。默认成本为零的“已验证证据回放”；`--live` 才会额外请求 DeepSeek。两种模式均不会更新 `reviews`，因此不改变实时、历史和 AI 页面。

## 里程碑 3：规则发布流程

每次规则调整先补回归样本，再运行影响报告、发布门禁和历史重审预览；确认后才保存新规则版本并发布。

已落地：规则快照、影响预览、版本校验、固定样本、发布门禁以及变更影响检查。规则影响由 Agent 自行判定，不需要业务方逐项回答。

## 里程碑 4：运行保障

完善来源失败、返回量异常、AI 失败率和人工推翻率监控；每日质量报告、备份、回退标签和异常告警形成固定运行机制。

已落地：来源失败、确定性污染和 AI 展示不一致已触发质量告警；本轮补充 AI 评测账本。下一步只会在有足够运行基线后启用“返回量突降”告警，避免把正常去重误报为故障。

## 里程碑 5：验收与持续协作

每次需求均明确目标、不变项、规则和正反样例；每次交付均提供影响范围、验证结果、数据影响、回退点与观察项。

已落地：`docs/变更验收清单.md` 为每次交付的固定输入/输出；用户侧只需给出目标、不可变约束和示例，Agent 负责影响检查、规则同步、测试与交付证据。
