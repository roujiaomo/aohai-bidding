# 遨海商机雷达｜架构与质量治理

规则版本：`2026.08.30-governance-v1`

## 处理边界

1. **来源与解析层**：抓取、原文保存、字段规范化；不作业务臆测。
2. **规则层**：硬排除、评分、去重、时效和展示状态，统一由有效规则快照驱动。
3. **AI Harness 层**：先抽取带原文证据的事实，再由程序决定业务桶；AI 不可直接把推断写成公告事实。
4. **展示层**：只读取正式评审状态，不回写原始公告。

## 状态机

`pending → approved / exclude / failed / expired`；AI 通过或排除后可人工确认：

- `approved → approved_manual / rejected_manual / expired`
- `exclude → approved_manual / rejected_manual / expired`
- `failed → pending`（重试）
- `expired → pending`（重新发现或恢复后）

人工结论仅控制实时/历史列表显示和业务桶，不删除原始公告；完整历史留在评审库和人工样本库。

## 发布质量门禁

每次规则、解析器、AI Harness 或 Prompt 修改，都必须执行：

1. Python 编译与单元测试；
2. 固定回归样本的预期分类校验；
3. 规则快照与摘要（版本、哈希、修改影响）；
4. 数据库只读质量报告；
5. 抓取和 AI 服务健康检查。

任何一项失败不得部署；数据迁移必须先输出预览，确认后才执行，且只软删除或写入历史快照。
