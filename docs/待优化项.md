# 待优化项

> 目标：以数据准确度为第一优先级，在不丢失可参与商机的前提下减少噪声，并让每项结论可追溯、可复核、可回退。
>
> 本文件是逐项实施清单。任何影响抓取、入库、时效、AI 裁决、展示或通知的实施，仍须同步更新 `docs/整体程序规则.md`、回归样本和发布门禁。

## 实施原则

1. 先量化再调整：没有标准样本和对比指标，不修改关键词、评分线或 AI 规则。
2. 原文优先：采购对象、项目阶段、参与入口和截止时间必须能回溯至公告原文。
3. 保守入池：证据不足的相关公告进入待核实或市场情报，不进入实时直接商机。
4. 人工结论优先：自动任务只更新派生状态，不覆盖人工最终结论。
5. 先预览后写入：涉及历史数据时先备份和只读预览，保留审计快照与回退点。

## P0：建立准确度基线

- [ ] 建立 200–300 条人工标注标准样本集。
  - 覆盖直接商机、市场情报、AI 排除、过期公告、结果公告、合同/验收、招聘/招租，以及 AIS、VDES、卫星、北斗等边界场景。
  - 每条保存人工最终桶、判定理由、原文引文和是否仍可参与。
- [ ] 建立离线回放工具，对规则或模型变更输出新旧差异清单。
- [ ] 固定发布指标：直接商机精准率、直接商机召回率、市场情报准确率、噪声漏入率、时效错误率、证据合格率。
- [ ] 将指标纳入发布门禁；指标下降时阻断发布并列出差异样本。

**验收：** 能针对任一次规则、抓取或模型改动，给出样本集上的量化前后对比和逐条差异。

## P0：每日时效与通知复核

- [ ] 增加每日可见性复核任务，重新检查实时商机的结构化截止日期与公告正文参与窗口。
- [ ] 区分投标/响应/递交/开标时间、获取文件/提问截止时间和合同履约时间；只有前一类决定是否仍可参与。
- [ ] 已截止记录从实时页和钉钉候选中移除，保留原始公告、AI 结论和历史商机。
- [ ] 输出当日过期移除数量、截止依据、解析失败数量和待人工核实数量。

**验收：** 已截止项目不会继续出现在实时页或通知中；未截止项目不会因获取文件或履约日期被错误隐藏。

## P1：来源抓取质量控制

- [ ] 为每个来源定义字段契约：标题、详情链接、发布时间、采购单位、正文、截止时间的最低质量要求。
- [ ] 缺少关键字段或正文过短的记录标记为待补全，不直接进入 AI 候选池。
- [ ] 记录列表页数量、抓取页数、详情成功率、正文长度、日期提取率与链接有效率。
- [ ] 为来源返回量、正文为空率和详情失败率建立基线与异常告警。
- [ ] 保存正文哈希、抓取时间和详情补全状态；同链接内容变化时触发重新提取与评审。

**验收：** 任一来源改版、返回量骤降或正文质量异常均可被发现；关键字段缺失不会静默进入有效商机。

## P1：去重与项目生命周期

- [ ] 明确三层去重：同链接更新、跨来源相同公告合并、相同项目不同阶段关联。
- [ ] 将招标、澄清、变更、结果等公告关联为项目链路，保留各阶段原始内容和来源。
- [ ] 官方来源优先作为正文和链接主来源，商业聚合来源作为补充来源。
- [ ] 已删除、已过期或已人工定案的记录被再次抓到时，只补充事实与来源，不自动改变人工结论。

**验收：** 同一项目不会重复推送；结果或变更公告不会覆盖仍可参与的招标公告；项目全链路可追溯。

## P1：AI 评审准确度闭环

- [ ] 保持“模型抽取事实、程序验证证据、程序决定实时入池”的职责边界。
- [ ] 将采购对象、项目阶段、参与入口、截止证据、业务相关性、排除事实分别输出并分别校验。
- [ ] 对低置信度、正文不完整、日期不明确或规则冲突的记录优先进入待核实，不强行通过或排除。
- [ ] 将已复核的人工改判沉淀为高质量纠错样本；禁止直接把所有人工点击变成规则。
- [ ] 规则或模型调整先对生产副本只读双跑，输出业务桶、证据、时效与失败率差异，再决定是否发布。

**验收：** 每个 AI 通过或排除结论均有可验证原文证据；模型调整不直接改写线上结论或人工决定。

## P2：面向准确度的使用体验

- [ ] 实时商机首屏展示：可参与状态、截止倒计时、业务桶、原文采购对象、推荐理由、来源、采购方、预算、地区和人工状态。
- [ ] 增加“待核实”队列，集中低置信度、正文不完整、日期不明确和规则冲突记录。
- [ ] 待核实记录仅提供三种结论：直接商机、市场情报、排除；排除必须填写原因。
- [ ] 增加数据健康页：来源最后成功时间、当日抓取/去重/待补全/待核实/AI 失败数、过期移除数和 7 天趋势。
- [ ] 完善筛选与溯源：未截止、三日内截止、业务桶、来源、地区、采购方、产品方向、原文引文、项目关联公告和审核历史。
- [ ] 所有影响展示状态的操作明确显示去向，并保留二次确认与审计记录。

**验收：** 用户无需打开详情即可判断是否值得跟进；异常来源、待核实记录和数据质量问题可在一个页面发现。

## 推荐实施顺序

1. P0 标准样本集、离线回放和指标门禁。
2. P0 每日时效与通知复核。
3. P1 来源字段契约、抓取健康监控与正文/日期质量控制。
4. P1 去重与项目生命周期。
5. P1 AI 双跑与人工纠错闭环。
6. P2 实时商机决策信息、待核实队列和数据健康页。

## 每项发布要求

每一项实施前后都必须记录：影响范围、标准样本指标、新旧差异、历史数据处置结论、备份与回退点、自动化测试和人工验证结果。涉及历史记录写入时，必须先备份、只读预览并保留审计快照。
