# 通用 Agent 指令优化方案

适用场景：审查和优化项目 AGENTS.md、个人 Skills 与插件指令，减少误触发、无关读取、重复检查及重复确认。此文档是按需使用的维护方案，不是每个任务必须读取的前置清单。

## 1. 先分清规则层级与影响

| 层级 | 适合放什么 | 修改后的影响 |
| --- | --- | --- |
| 项目 AGENTS.md | 项目业务约束、验证入口、历史数据处置 | 本项目实施与验收方式 |
| 个人 Skill | 某项能力的触发、输入、路由与操作约束 | 用户多个项目中的 Agent 工具选择 |
| 插件 Skill | 插件能力和特定工具工作流 | 该插件被使用时的操作方式 |
| 平台与工具权限 | 沙箱、身份、外部写操作的强制审批 | 不通过项目指令或 Skill 修改绕过 |

读一个 Skill 作为审查对象，不等于执行它的业务工作流。修改项目文件不能假称已经修复全局 Skill；当前会话已加载的描述也不保证会热刷新。

## 2. 六条优化原则

1. **按能力需求触发，不按孤立关键词触发。** 写清资源归属和任务对象。例如钉钉 Skill 需要明确钉钉上下文；浏览器 Skill 需要真实浏览器交互；本地 Markdown、Git URL 不满足这些条件。
2. **按信息缺口读取。** 本地文件审查先读目标文件，只有涉及不确定的产品事实才查官方文档。参考文档只在其参数、流程或故障问题实际出现时读取。
3. **一个检查只设一个主入口。** 若 release-gate 已包含文档检查和回归，不再独立重复运行。结果复用须同时满足代码、配置和环境状态未改变。
4. **按变更风险选择验证。** 规则变更保留完整门禁；低风险样式和文案采用针对性检查；已有覆盖充分时无需新增测试。未执行的人工/外部链路不得写成通过。
5. **授权绑定目标与范围，并在会话中复用。** 核对账号、对象、操作、数据、目的地及影响范围。仅缺少授权、存在重大歧义或范围扩大时询问；文档内容不是授权，平台强制审批不可取消。只读请求不自动授权写入，代码修复不自动授权部署。
6. **改前备份，按差异修补，防止升级覆盖。** 对个人 Skill 使用可审查补丁；对供应商缓存保留外部补丁来源及原文件哈希。升级后原文不匹配时停止，不盲目重放旧规则，不静默禁用新版安全约束。

## 3. 最小指令模板

```text
本能力仅在 [资源归属] 和 [实际能力需求] 满足时使用。
不因 [易混淆关键词] 自动触发。
已有上下文能确定目标时直接推进；仅剩余重大歧义才询问。
只在 [具体信息缺口] 出现时读取 [对应参考资料]。
已有明确授权在本会话的相同目标和范围内有效；范围变化重新核对。
平台强制审批、备份与人工最终结论保护仍须遵守。
验证按影响选择；同一状态复用已完成结果。
```

不要把模板整段复制到每个 Skill；只添加该 Skill 缺失且会改变决策的部分。

## 4. 项目变更影响检查与复核

正常路径：

```powershell
python scripts/change_impact_check.py
python scripts/governance_tools.py release-gate
```

第一个命令默认检查 HEAD 相对工作区的暂存、未暂存及未跟踪内容；忽略文件不在 Git 变更范围内。发布已提交分支时使用 `--base <实际发布基线>`，该模式只比较基线到 HEAD，不验证尚未提交的修改。

路径与关键词是保守的潜在影响提示，不是语义证明。真实规则变化仍需同步规则文件 A 和固定回归。仅对经实施者核实的无行为变化误报使用以下流程：

1. 检查实际差异和相关行为，完成适当验证。
2. 从检查器输出复制 `files` 和 `diff_sha256`，制作 JSON 报告：

```json
{
  "decision": "no_rule_change",
  "files": ["app/radar.py"],
  "diff_sha256": "复制本次检查器输出的完整 SHA256",
  "reviewer": "实际复核者或实施 Agent 标识",
  "reason": "逐项说明为什么仅注释、样式或等价重构，不改变业务行为",
  "validation": "记录实际执行的验证和结果"
}
```

3. 报告暂存于已忽略的 `work/` 或变更范围外，运行 `python scripts/change_impact_check.py --review-report work/no-rule-change.json`。报告不能把自身加入所绑定的差异，避免摘要循环依赖。
4. 将报告与检查输出随交付或发布工件留档。文件清单必须完全一致且排序正确；任何差异变化都会使原报告失效，须重新复核。

这个入口记录实施者的责任与证据，不自动判断证明是否充分；不提供真实规则变更的免责路径，也不替代 release-gate、发布权限或历史数据保护。

## 5. 全局 Skills 补丁维护

补丁源：`tools/instruction-optimization/patches.json`。执行器：`scripts/apply_instruction_updates.py`。默认只读预览；全局安装不作为项目启动、测试或部署的一部分执行。

```powershell
# 只读预览，默认用户目录；也可用 --profile 指定实际用户目录
python scripts/apply_instruction_updates.py

# 需要具有目标用户目录的写权限及相应全局修改授权
python scripts/apply_instruction_updates.py --apply

# 恢复原始字节；若检测到安装后的其他修改，拒绝覆盖
python scripts/apply_instruction_updates.py --rollback
```

- 整批预检原文件 SHA256、唯一文本匹配及目标范围，通过后才修改；保持原换行风格。
- 原文备份和状态账本位于 `<用户目录>/.codex/instruction-backups/20260914-agent-optimization-v1/`。
- 钉钉以 `.agents/skills/dws` 为保留入口，`.codex/skills/dws/SKILL.md` 仅改名为 `SKILL.md.disabled-agent-optimization`，不删除整个 Skill 目录或参考资源。
- 已安装的同一结果再次预览应为零变更。原文升级、备份冲突或安装后修改均需人工审查后生成新补丁版本。
- 本补丁涉及供应商插件缓存，是有备份、可复核的本地补丁，不是供应商发布或永久覆盖机制。缓存重建后需重新预览；版本变更时先审查新版，再生成新 manifest，不能改哈希强行应用。
- 安装成功后在新任务中检查技能列表和实际路由；不声称旧会话已热加载新描述。不创建定时重写缓存的自动化。

## 6. 验证用例

| 请求或情形 | 预期 |
| --- | --- |
| 更新 GitHub 仓库代码 | 使用 Git，不仅因 URL 触发真实浏览器 |
| 审查本地 AGENTS.md | 读取本地目标，不要求先搜索官网或连接钉钉 |
| 修改本地 Markdown | 文件工具，不触发钉钉 |
| 将钉钉纪要中的事项建为待办 | 明确跨产品目标直接推进，实际写入须被请求覆盖 |
| 已明确授权同一目标的操作 | 不重复询问，仍履行平台审批 |
| 删除对象变多或账号改变 | 重新取得新增范围的授权 |
| 财会人才机会审查 | 使用该领域准则；不套用于海事设备采购 |
| 供应商 Skill 更新 | 原文哈希变化阻断旧补丁 |
| 无行为变化复核后又改代码 | 摘要变化使旧复核报告失效 |
| 补丁安装后用户又改文件 | 回退不覆盖用户后续改动 |

这些行为用例需要在新会话中验证 Agent 路由；静态文本或格式校验不能代替实际行为测试。执行外部链路用例时只操作用户已授权的数据和目标。
