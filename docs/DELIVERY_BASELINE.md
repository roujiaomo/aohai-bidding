# 遨海商机雷达：交付基线

## 结论

当前版本可用于内部试运行，不应在没有下面“上线门禁”的情况下作为无人值守的正式交付版本。

## 当前真实架构

```text
公开/授权数据源
  -> 来源适配器与详情页回填
  -> 确定性入库闸门（标题、公告类型、相关性、日期、去重）
  -> radar.db（唯一实时商机库）
  -> AI 候选同步（有效期与实时页同口径）
  -> DeepSeek + 服务端硬约束
  -> ai_review.db
  -> 实时商机（直接商机 / 市场情报）与 AI 排除复核
```

生产路径：

- 雷达服务：`/opt/bidding-ai-radar`、`data/radar.db`。
- AI 服务：`/opt/bidding-ai-review`、`data/ai_review.db`。
- 旧目录 `/opt/bidding-cli` 已封版，不得再作为任务的工作目录或数据库路径。

## 规则的唯一来源

| 规则类别 | 唯一来源 | 消费者 | 变更后的生效方式 |
| --- | --- | --- | --- |
| 检索词、相关性词、评分、区域、客户词、展示标签 | `radar.db` 同目录的 `config.json` 中 `rules` | 抓取、入库、实时页、帮助页 | 下次抓取；帮助页每次打开刷新 |
| 时效、保留期、链接校验 | 同一 `config.json` | 入库、实时页、AI 同步 | 下次抓取/同步 |
| 遨海能力、直接商机/市场情报/排除定义 | `services/ai-review/ai_review.py` 及 AI 服务 `config.json` | AI 评审、数据规则只读页、帮助页 | AI 服务重启；帮助页每次打开刷新 |
| 人工判定样本 | `ai_review.db.human_review_cases` | 后续 AI 学习辅助规则 | 下次 AI 评审 |

禁止把同一业务口径复制到多个可编辑页面。数据规则页的 AI 页签必须只读并实时读取 AI 服务；帮助页必须读取上述两个服务端来源。

## 当前业务口径

### 直接商机

必须仍存在公开参与入口，且符合任一条件：

1. 海事语境中明确采购 AIS、VDES、船站/船载终端、岸基站/通信基站、船岸通信、航标遥测遥控、ECDIS/INS 或海事数据平台；
2. 智慧航道、VTS、智慧港口/海洋等集成项目，原文明确船舶信息、通航安全、通信导航、调度监管或海洋数据平台范围。

资格、业绩、授权、联合体、技术细节缺失只形成“待确认”，不单独降级。

### 市场情报

业务相关但已无参与入口，或属于中标/成交结果、可研设计规划、无明确采购范围的泛化线索。

### 排除

招聘、废标/终止、合同/验收、环评；电力行业 AIS 开关设备；普通照明、保险、培训、会议、劳务，以及无海事电子信息实质采购关系的项目。

## 上线门禁（缺一不可）

1. **变更可追溯**：每次规则或代码变更必须有 Git 提交、规则版本、变更原因、影响范围和回滚点。
2. **发布前测试**：单元测试覆盖日期、公告阶段、AIS 歧义、电力 AIS、结果公告、直接产品、集成项目、去重；发布后执行接口冒烟测试。
3. **抓取可观测**：每个来源记录返回数、新增数、更新数、拒绝数、详情失败数、最后成功时间和最后错误；失败来源不得显示为“已接入/健康”。
4. **数据质量门禁**：每日只读审计并生成报告，监控非法日期、过期仍展示、AI 通过与实时页不一致、重复、零正文、来源连续失败、规则拒绝率突变。
5. **AI 可审计**：每条结论保存模型版本、规则版本、原文证据、服务端覆盖原因、人工复核结论；规则升级必须在固定回归样本集上比较差异后才能批量重审。
6. **可回滚**：每次批量迁移/重审前备份两个数据库和任务定义；只允许先预览、再人工确认执行。

## 当前阻断项

1. 来源状态与实际抓取结果没有统一健康模型；适配器吞掉异常时可能仍被标为 `connected`。
2. 现有自动测试主要覆盖入库策略和单一来源，尚未覆盖 AI 时效、AI 桶映射、规则同步、服务路径和抓取失败状态。
3. 规则版本没有独立持久化快照；目前只能依赖代码提交与数据库备份回溯。
4. 没有定时质量报告、失败告警和上线前回归样本门禁。

## 建议的正式交付顺序

1. 先实现来源健康与抓取运行账本，并修复“失败显示已接入”。
2. 建立规则版本快照、固定回归样本和自动测试。
3. 增加每日质量报告与失败告警；连续 7 天稳定后再开放给最终用户。
4. 建立发布流程：开发分支 -> 预发布库回放 -> 验收 -> 备份 -> 生产发布 -> 冒烟 -> 回滚窗口。
