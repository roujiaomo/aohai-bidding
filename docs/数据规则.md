# 遨海商机雷达｜数据规则基线

> 当前生效的机器可读规则由服务端 `/api/rules` 返回；其中 `_governance.version` 与 `_governance.digest` 是本规则快照的唯一版本标识。帮助页、抓取评分、质量报告和规则影响预览均读取该有效规则快照。修改前必须运行 `python scripts/governance_tools.py reprocess-preview`，发布前必须运行 `python scripts/governance_tools.py release-gate`。

> 版本：2026-08-25  
> 适用范围：当前线上服务与本仓库 `app/radar.py`、`config.json`。  
> 用途：后续修改关键词、评分、去重、筛选或天眼查抓取前，先以本文为影响评估基线。

## 1. 数据对象与处理顺序

一条公告在进入看板前依次经历：

```text
来源抓取 → 字段标准化 → 链接/详情补全 → 评分 → 噪声闸 → 去重 → 入库 → 实时筛选/历史留存 → 提醒
```

核心字段：

| 字段 | 说明 |
|---|---|
| `source_code` / `source_url` | 来源及原始链接；多来源合并时来源码以逗号拼接 |
| `title`、`buyer`、`region`、`content` | 评分、检索、去重与展示的主要业务字段 |
| `published_at`、`deadline_at` | 实时页有效性判断；均使用北京时间语义 |
| `score`、`match_json` | 总分及各项命中明细 |
| `priority` | 重点关注 / 值得跟进 / 一般关注；可人工修改 |
| `followup_status`、`is_deleted` | 过期状态与软删除状态 |
| `category`、`agency`、`winner` | 商机种类、代理机构、中标单位等辅助信息 |

## 3. 业务关键词与评分

### 3.1 基础评分

每个业务分类独立计算：命中 `n` 个关键词，分类得分为：

```text
min(该分类权重, 8 + 7 × n)
```

各分类得分相加；若所有业务分类都未命中，公告直接为 0 分且不入库。

关键词命中还必须通过分类语境门槛：卫星类须同时出现低轨、星座、轨道、载荷、星地、卫星平台/地面站等航天语境、“卫星 + 系统/终端/天线/基站/节点/链路/测控/维保”等明确工程对象或服务，或者明确的船舶、海事、海上应用语境；其他分类须有海洋、内河、船舶、航道、航标、港航或水运语境。明确的“航道、航标、海洋、船舶、卫星互联网、低轨卫星”等短语可自证对应语境；“搜救、北斗、卫星通信、遥感监测、高精度定位”等宽泛词单独出现不计分。来源检索词不因此删减，原始抓取仍保持宽召回。

| 分类 | 权重 | 代表关键词 |
|---|---:|---|
| AIS/VDES 与海事通信 | 35 | AIS、VDES、岸基站、甚高频、VHF、航标遥测、船岸通信、海事卫星 |
| 通航安全与智慧航道 | 28 | VTS、智慧航道、数字航道、电子航道图、航道整治、航标工程 |
| 卫星互联网与航天软件 | 20 | 卫星互联网、低轨卫星、卫星通信、卫星物联网、星地融合 |
| 北斗与时空服务 | 16 | 北斗、船舶定位、时空大数据、遥感监测、高精度定位 |
| 海洋资源与海岸工程 | 18 | 海洋观测、海上风电、海岸工程、海洋测绘、海底电缆、智慧海洋 |
| 相关延展场景 | 10 | 智慧港口、港航一体化、水上应急、水运工程、港口工程、码头工程 |

### 3.2 隐藏重点规则

公告**标题**以不区分大小写的独立缩写命中 `AIS` 或 `VDES`，并通过海事语境确认时，额外加 **30 分**。

- 只检查标题，不检查正文；避免正文中无关缩写、培训活动等误触发。
- 该加分与分类、区域、采购方、预算加分累加，最终总分仍封顶 100。
- 命中详情写入 `match_json`，标签为“AIS/VDES 标题重点规则”。
- 该规则不在前端规则编辑区暴露；修改需直接评审代码并回算存量数据。

### 3.3 其他加分

| 条件 | 加分 | 判定字段 |
|---|---:|---|
| 一级重点区域 | +15 | `region` |
| 二级重点区域 | +8 | `region`，与一级不叠加 |
| 采购方关键词 | `min(20, 8 + 4×命中数)` | `buyer` |
| 预算不低于 50 万元 | +8 | `budget` |

一级区域：辽宁、山东、北京、上海、江苏、安徽、江西、湖北、湖南、重庆、四川、广东、广西。  
二级区域：天津、河北、浙江、福建、海南。  
重点城市仅用于命中说明，不单独增加分数。采购方词库以海事局、航道局、交通运输、港口、港务、水利、三大运营商、国家电网、南方电网、能源央企、华润、国铁、集团等为主。

### 3.4 商机优先级

| 总分 | 自动优先级 |
|---:|---|
| ≥80 | 重点关注 |
| 50–79 | 值得跟进 |
| <50 | 一般关注 |

自动优先级仅在入库或受控回算时设置；用户手工修改后的优先级不得被常规重抓覆盖。

## 4. 商机种类

按标题依次匹配，先命中的分类生效：

1. **前期线索**：勘察设计、可研、前期咨询、规划设计、全过程咨询等；
2. **直接产品**：AIS、VDES、岸基站、甚高频、北斗、航标遥测、船岸通信等；
3. **集成项目**：智慧航道、航道整治、VTS、航道/港口工程、疏浚、智慧海洋、水上应急等。

未命中不打种类标签。分类本身不改变评分。

## 5. 噪声闸

评分大于 0 后仍需通过标题质量判断：

1. 标题含招标、采购、中标、成交、询价、比选、公告、公示等招采特征词：放行；
2. 标题命中通知、工作计划、部门预算、薪酬、考试、录用、监督检查等新闻/政务噪声：拒收；
3. 裸机构名：拒收；
4. 截断标题或含标段、监理、测量、维保、工程、项目等结构词：放行；
5. 其余标题必须自身命中业务关键词；仅正文命中业务词不放行。

此规则的目标是防止官网全站抓取时，新闻、招聘、预算披露因正文碰词进入商机库。

## 6. 去重与轮次保护

### 6.1 允许合并

- 同一来源、同 URL、同标题、同采购方、同发布日期的指纹重复；
- 同阶段、同轮次、标题主体高度相似的跨来源转载或标题变体；
- 合并后保留较优正文/字段，并累加来源码。

官方来源优先于商业聚合来源（天眼查）：官方标题、链接和正文优先保留。

### 6.2 禁止合并

- 招标、变更、中标、成交、废标、流标、终止、合同、验收等不同公告阶段；
- 一标、二标等不同标段；
- 首轮、二次、三次、重新招标、再次招标等不同采购轮次；
- 尾部截断标题仅可精确同标题合并，不能模糊合并。

标题归一化可删除无业务含义的尾部括号标签，但保留“二次/三次”等轮次信息。这是防止二次公告被错误并回首轮公告的硬性规则。

## 7. 实时、历史、删除规则

| 视图/状态 | 规则 |
|---|---|
| 实时商机 | `is_deleted=0`、非手动过期；截止日未过期；无截止日时发布日期在 30 天窗口内 |
| 历史商机 | 仅排除软删除，不按 30 天窗口过滤 |
| 回收站 | `is_deleted=1`，可恢复 |
| 手动过期 | `followup_status=expired`，实时页不显示 |
| 自动清理 | 每轮常规抓取结束后删除超过 365 天的已发布日期记录 |

## 8. 天眼查分层检索规则

天眼查额度有限，普通全源抓取不再包含天眼查；由独立任务执行。

| Profile | 词 | 窗口 | 时间 | 分页 |
|---|---|---:|---|---|
| `critical` | AIS、VDES、AIS岸基、AIS基站 | 3 天 | 每 4 小时 | 100 条/页，最多 2 页 |
| `core` | 航道、航标、甚高频、海事通信、数字航道、智慧航道 | 7 天 | 01:00、09:00、17:00 | 100 条/页，最多 1 页 |
| `expansion` | 船舶、卫星、智慧海洋、智慧港口、海洋风电 | 14 天 | 每日 12:30 | 100 条/页，最多 1 页 |
| `delay_backfill` | 同关键层 | 7 天 | 每日 13:15 | 100 条/页，最多 3 页 |

分页停止条件：当前页返回少于 100 条时立即停止。已验证：100 条页面只扣一次有效调用；空页不扣额度。常规日预计约 51 次查询，深分页全部触发时上限约 83 次，低于每日 100 次额度。

## 9. 修改规则的操作要求

1. 先明确影响范围：未来入库、存量回算、实时列表、提醒是否受影响；
2. 修改前备份 SQLite；
3. 对新增关键词至少准备真商机、噪声、边界标题各一例；
4. 修改评分、优先级或去重后，执行单元测试和生产只读核验；
5. 如改变存量分数，只更新仍处于自动优先级的记录，保留人工优先级；
6. 涉及天眼查关键词、页数、频率时，先评估日额度上限并观察 7 天有效率。
